# Personal Impact 工作流（个人目标分析）

**默认关闭。** 仅当用户**主动要求**且**自行提供个人目标**时执行。与客观事实调查**物理隔离**。

## 前置条件（硬约束）
- 用户显式开启（例如"结合我的情况分析""分析对我的影响"）。
- 用户提供目标文本（如"我想做独立开发者""我是 3 年前端，担心被替代"）。
- 若未提供目标却要求分析 → **拒绝**，提示用户先提供目标；**绝不**默认读取记忆/文件/历史。

## 输入
- `user_goal`：用户自述的目标/背景（来自用户输入，非自动采集）。
- 已完成的事实调查结论（claims_detail / verdict / technical_reality / practical_barriers）。

## 步骤
1. **相关性判断**
   - 该技术与用户目标是否相关？相关维度（成本、技能门槛、时间投入、风险）。
2. **适用性分析**
   - 基于事实调查的"真实能力 + 实际门槛"，判断用户当前条件是否匹配。
   - 区分"现在就能用" vs "需先补 X 才能用"。
3. **建议**
   - 给出可操作建议（学什么、避什么坑、优先级），基于证据而非鼓励/恐吓。
4. **风险与 caveat**
   - 指出该主张中的夸大/不确定点对用户决策的具体影响。
   - 明确本分析基于"当前证据"，技术演进可能改变结论。

## 输出
写入报告独立字段 `personal_impact`：
- `user_goal`（回显用户目标）
- `relevance`（相关度说明）
- `recommendation`（建议）
- `caveats`（风险/注意）

## 隔离原则
- 个人影响结论**不得**反向修改事实 verdict / confidence。
- 个人影响章节与事实调查章节在 Markdown 中明确分隔。
- 不把"适合你"当作"技术已成熟"的证据。

## 隐私
- 仅使用用户本次对话中**主动提供**的信息。
- 不调用记忆/文件/历史；不把分析结果绑定到任何身份标识外发。
