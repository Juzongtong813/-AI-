# Deep Investigation 工作流（深度调查）

适用：重要技术突破、商业机会、职业影响等需要严谨判断的内容。范围完整，**证据标准与 Quick 一致**。

## 进入条件
用户明确要求 Deep，或内容属于上述高影响类别（可由 Agent 建议升级）。

## 步骤
1. **理解内容（完整）**
   - 提取实际展示；记录内容边界（哪些展示了、哪些只口头声称）。
   - 无法访问 → 标记信息不足 + 局限，结束或请用户补充。

2. **拆解主张（全量）**
   - 列出**所有** `verifiable=true` 的 claim，含隐藏前提拆出的子主张。
   - 观点类单独说明"不在可验证范围"。

3. **逐主张取证（交叉）**
   - 每条 claim：官方 + 独立实测 +（媒体/用户生成）多来源交叉。
   - 单主张来源建议 **4–8 个**，但重质量不重数量。
   - 强制双向：支持与反对各检索；找不到反证也明确记录"未找到可靠反证"。
   - 用 `scripts/dedup_sources.py` 辅助检查同源；`references/source-reliability.md` 判定独立性。

4. **成熟度 & 门槛（严格）**
   - 明确 Demo / 可用工具 / 成熟产品 三档判定 + 依据。
   - 应用门槛：成本、技能、环境、稳定性、合规，逐条说明。

5. **营销识别（严格）**
   - 逐条对照 8 种夸大模式（`references/marketing-detection.md`），引用原文 + 证据落差。

6. **证据矛盾处理**
   - 支持/反证质量相当时 → 该 claim 标 `contradicts_evidence` 或 `unverified`，并列矛盾点。
   - 一方明显更可靠 → 主导，但记录反方。

7. **生成报告**
   - JSON（先）→ `validate_schema.py` → `generate_report.py` 渲染 Markdown。
   - 全部章节齐全（见模板）：逐项验证、支持/反对证据、来源、技术现实、门槛、营销分析、局限、最终判断。

8. **（可选）个人目标分析**
   - 仅当用户显式开启并提供目标 → 走 `workflows/personal-impact.md`，结果写入独立字段。

9. **结论 + 局限**
   - 整体 verdict + confidence + 明确的未覆盖/未验证点。

## 范围（预算）
- 主张全量；单主张来源 4–8；证据高度一致可适当收敛，矛盾则充分展开。
- 不无上限检索；不堆来源。

## 质量红线
- 任何"已验证/成熟"结论必须有高/中可靠性独立证据支撑。
- 无证据支撑的断言一律 `unverified`，不伪造。
- 不绕过安全/隐私原则（见 `references/investigation-principles.md`）。
