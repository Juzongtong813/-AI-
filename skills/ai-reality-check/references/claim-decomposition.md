# 主张拆解规则 (Claim Decomposition)

目标：把一条视频/帖子从"情绪化表达"变成"可逐个验证的具体主张"。

## 输入
- `content_summary`：对"视频/内容实际展示了什么"的客观描述（来自 SKILL.md Step 1）。

## 输出
`core_claims[]`，每条：
- `id`：C1、C2、C3…
- `claim`：用中性语言重述的可验证断言，**保留原文引用**（用引号或"原话：…"）。
- `category`：九类之一（见 PRD §6）：
  `model_breakthrough` / `ai_tool` / `vibe_coding` / `content_creation` / `game_dev` / `money_making` / `startup` / `job_impact` / `other`
- `verifiable`：`true`（可被证据支持或反驳）/ `false`（纯观点、无法证伪）。

## 拆解步骤
1. **去标题化**：先看内容实际演示，不被标题带节奏。标题可能是夸大，内容可能是另一回事。
2. **抽具体断言**：把"AI 太强了"拆成"在 X 条件下，AI 能完成 Y（例如：输入一句话，工具生成了一个可运行的 2D 平台游戏 Demo）"。
3. **标隐藏前提**：遇到"只要…就…""无需…也能…"，把前提单独拆为子主张。例如"不懂编程也能开发商业软件"→ 拆为：
   - C_a：该工具允许零代码生成应用（可验证）
   - C_b：生成结果达到"商业可用"标准（可验证，常需额外人工）
4. **去情绪与观点**：过滤"再不学就晚了""太炸裂了"等不含可验证信息的句子。
5. **去重合并**：同一事实的多种表述合并为一条。

## 判定 verifiable
- 可被第三方证据支持或反驳 → `true`。
- 主观感受、预测性口号（"未来所有人都会失业"）→ `false`，标记为观点，不进入取证，但在报告中说明"此为观点，不在本次可验证范围"。

## 示例
内容：*"我用 AI 一天做了 3 个 App，赚了一万块，不懂代码也能搞钱。"*

拆解：
- C1（money_making, true）：该作者声称"用 AI 一天做了 3 个 App"。
- C2（money_making, true）：该作者声称"用 AI 一天赚了 1 万元"。
- C3（vibe_coding, true）：该作者声称"不懂代码也能用 AI 开发 App"。
- C4（vibe_coding, true，隐藏前提）：所开发 App 达到"可发布/可盈利"的商业标准。
- （"搞钱"为情绪词，不入 claim。）

## 注意事项
- 不要替用户"脑补"主张；只拆内容里实际出现的。
- 若内容过于模糊，无法拆出任何 `verifiable=true` 的 claim → 输出"无可验证主张"，并说明原因，进入停止分支（见 investigation-principles）。
