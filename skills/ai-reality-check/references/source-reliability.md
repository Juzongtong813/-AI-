# 来源可靠性与独立性 (Source Reliability & Independence)

## 1. 来源类型 (type)
- `official`：官网、官方博客、论文、模型卡、发布说明。
- `independent_test`：独立评测、复现实验、第三方 benchmark。
- `academic`：同行评审论文、预印本（arxiv 等，标注未评审）。
- `media`：新闻机构报道。
- `user_generated`：论坛(知乎/Reddit/HN)、评测视频、GitHub issues/discussions。
- `marketing`：厂商广告、带货自媒体、赞助内容。

## 2. 可靠性 (reliability)
- `high`：官方一手 + 可复现；或多独立来源一致；同行评审。
- `medium`：单一可信独立实测；知名媒体事实报道。
- `low`：无出处自媒体；情绪化；无法复现；纯观点。

## 3. 来源独立性 (independence) — 核心防坑
**问题：** "10 家媒体都在说"可能只是"1 条通稿被 10 家转载"。把它们当 10 个独立证据会严重高估可信度。

**判定方法：**
1. 看多个来源是否引用**同一原始出处**（同一论文 DOI、同一官方公告、同一原始视频、同一篇 PR）。
2. 若同源 → 在 `independence_note` 标注"与 X 同源（通稿/转载）"，**合并计数**。
3. 真正独立 = 不同团队、不同方法、得出一致结论。
4. 用 `scripts/dedup_sources.py` 辅助：检测 URL 同域名同源、标题余弦相似、引用同一 primary source。

**示例：**
- A 媒体、B 媒体、C 自媒体都报道"某模型登顶榜单" → 若三者都引用同一官方公告 → 算 1 个独立证据（官方），而非 3 个。
- 官方公告 + 独立实验室复测均确认 → 2 个独立证据，可靠性高。

## 4. 共同出处合并规则
- 在 evidence_sources 中保留各条目（便于追溯），但 `independence_note` 显式关联。
- 在 claims_detail 的"证据强度"描述中，按**独立证据数**而非"提及条数"评估。
- 报告"支持证据/反对证据"章节应注明"其中 N 条同源"。

## 5. 标注模板
```
independence_note: "与 source#2 同源（均转引自厂商 2026-03 公告）；计为 1 个独立证据。"
```

## 6. 注意事项
- 用户生成内容（如 GitHub issues 中多人反馈同一 bug）可能代表真实广泛问题，但需区分"多人独立遇到"与"一人发帖被转发"。
- 营销内容即使被多家媒体转载，其原始声明仍只算厂商单方主张，非独立证据。
