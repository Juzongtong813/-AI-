# 证据评价标准 (Evidence Standard)

统一适用于 Quick Check 与 Deep Investigation。快速模式只减少范围，不降低本标准。

## 来源优先级（取证时从高到低尝试）
1. `official` — 官方文档、论文、发布说明、模型卡（model card）。
2. `independent_test` — 独立第三方的实测、复现、benchmark。
3. `academic` — 同行评审研究。
4. `media` — 新闻媒体报道（需区分报道 vs 观点）。
5. `user_generated` — 用户生成内容（论坛、评测视频、GitHub issues）。
6. `marketing` — 厂商/自媒体营销内容（权重最低，仅作"它声称什么"而非"事实"）。

## 来源可靠性 (reliability)
- `high`：官方一手、可复现实测、同行评审、多独立来源一致。
- `medium`：知名媒体、单一但可信的独立实测。
- `low`：单一自媒体、无出处、情绪化、无法复现。

## 取证动作（每条 claim）
1. 用准确名称（模型名/工具名/版本）精确检索。
2. 检索 "<tool> review / 实测 / limitation / 失败 / 踩坑 / 缺点"。
3. 检索反方观点与批评（例如 "why X is overhyped"、"X 翻车"）。
4. 对能力声明，优先找可复现的实测或官方文档；找不到则标 `unverified`。

## 技术成熟度三档 (maturity)
| 档位 | 定义 | 典型信号 |
|-----|------|---------|
| **技术 Demo** | 理想条件下的单次展示，常隐藏人工/编辑/限定输入 | "演示视频"、"需手动挑选输入"、"不可复现" |
| **可用工具** | 可下载/调用，有真实用户，但有门槛或局限 | 有公开可用版本、真实用户反馈、已知限制 |
| **成熟产品** | 稳定、可规模化、广泛可靠用例 | 大规模稳定使用、SLA、生态、长期维护 |

**铁律：**
- 不把 Demo 当成熟产品。
- 不把个例当普遍可复现。
- 标注实际应用门槛：成本、技能要求、运行环境、稳定性、合规。

## 证据矛盾处理
- 支持与反对证据均存在且质量相当 → 标注 `contradicts_evidence`（针对该具体断言）或整体 `unverified`，并**并列矛盾点**，不强行下结论。
- 一方证据明显更可靠（如官方实测 vs 单一自媒体） → 以更可靠方为主导，但仍记录反方。

## 证据记录字段（写入 evidence_sources[]）
`id` / `title` / `url` / `publisher` / `type` / `reliability` / `independence_note` / `accessed_at`

## 禁止
- 只用搜索引擎摘要，不下钻到原文。
- 只搜 confirm 不搜 refute。
- 用模型自身知识替代证据。
- 用无依据数字（"效率提升 1000%"）作为结论支撑。
