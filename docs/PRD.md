# AI Reality Check — 产品需求文档 (PRD)

> 版本：V1
> 状态：已实现
> 最后更新：2026-11-11

---

## 1. 产品定位

**AI Reality Check 是一个以 Agent Skill 为核心交付形式的开源 AI 信息现实调查工具。**

它不反对 AI 技术进步，而是帮助普通用户在社交媒体、短视频平台遇到令人焦虑或兴奋的 AI 相关内容时，区分"真实的技术进步"与"社交媒体制造的焦虑（AI FOMO）"。

用户把一条视频链接（或一段内容）发给正在使用的 Agent，Agent 调用 AI Reality Check Skill，自动完成"提取内容 → 拆解主张 → 搜索独立来源 → 收集正反证据 → 评估技术成熟度 → 识别营销夸大 → 输出可追溯调查报告"的全过程。

**核心交付形态是 Skill，不是独立产品。** 用户通过 GitHub 安装 Skill 到自己的 Agent，复用 Agent 已有的搜索、浏览、视频解析、代码执行、推理能力。

---

## 2. 目标用户

| 用户类型 | 典型特征 | 主要诉求 |
|---------|---------|---------|
| 普通互联网用户 | 在抖音/B站/YouTube/TikTok/小红书/X 刷到 AI 焦虑视频 | 快速判断"这是真的吗，跟我有关吗" |
| 开发者 / 独立创作者 | 关注 Vibe Coding、AI 游戏开发、AI 视频工具 | 判断工具是否真能落地，避免被 Demo 误导 |
| 创业者 / 副业者 | 看到"AI 一天赚十万"类内容 | 判断商业机会是否真实、门槛多高 |
| 职场人 | 看到"AI 让程序员失业"类内容 | 判断对自己职业的实际影响 |
| Agent 使用者 | 已在用某 Agent，希望扩展其能力 | 一键安装、即装即用 |

**非目标用户：** 需要学术级文献综述的科研人员（本工具定位为面向普通人的快速现实核查，不替代严谨学术调查）。

## 3. 核心使用场景

用户在任意平台看到一条 AI 相关视频/帖子，例如：

- "AI 已经可以一键生成完整游戏。"
- "一个人利用 AI 一天就能赚十万元。"
- "某新模型让传统程序员失去价值。"
- "某工具可以完全替代视频制作团队。"
- "不懂编程的人也可以批量开发商业软件。"

用户将链接（或文字内容）发给 Agent，Agent 调用本 Skill，产出一份带证据出处的调查报告，并在用户主动开启时分析该技术与用户个人目标的关系。

## 4. 功能需求

> 每个功能均描述：输入 / 处理逻辑 / 输出 / 异常情况。

### F1. 内容理解
- **输入**：视频链接、或粘贴的文字/字幕/截图转写文本。
- **处理逻辑**：优先提取视频真实展示的内容（画面、演示步骤、前后条件），而非仅看标题与文案。若只有标题无实质内容，明确标记信息不足。
- **输出**：`content_summary`（客观描述"视频实际展示了什么"）、`content_meta`（平台、作者、标题、时长等）。
- **异常**：链接无法访问、无字幕/无转写、区域限制 → 进入"信息不足"分支，不臆测内容，输出局限性说明。

### F2. 主张拆解
- **输入**：`content_summary`。
- **处理逻辑**：把内容拆成可独立验证的具体主张（claim），每条带编号、原文引用、主张类型、可验证性判定。过滤纯情绪表达与无法证伪的主观评价。
- **输出**：`core_claims[]`（id、claim、category、verifiable）。
- **异常**：内容过于模糊无法拆出具体主张 → 输出"无可验证主张"，附原因。

### F3. 证据收集（支持 + 反证）
- **输入**：每条 claim。
- **处理逻辑**：为每条主张主动搜索支持证据与反对证据，优先官方文档与独立实测；记录来源独立性（是否同一原始出处被多媒转载）。
- **输出**：`evidence_for[]`、`evidence_against[]`、`sources[]`。
- **异常**：搜索无果 → 标注"未找到独立证据"，不判定为"假"，只标注"未验证"。

### F4. 技术成熟度评估
- **输入**：证据。
- **处理逻辑**：区分 **技术 Demo / 可用工具 / 成熟产品** 三档，并评估实际应用门槛（成本、技能、环境、稳定性）。
- **输出**：`technical_reality`、`practical_barriers`。
- **异常**：证据互相矛盾 → 标注"证据矛盾"，分别列出矛盾点，不强行下结论。

### F5. 营销夸大识别
- **输入**：原始表述 vs 实际证据。
- **处理逻辑**：识别标题党、选择性展示、隐藏前提、混淆 Demo 与产品、用个例代表普遍、无依据的百分比/收益。
- **输出**：`marketing_analysis`（逐条指出夸大点）。
- **异常**：无夸大迹象 → 明确写"未发现明显夸大"。

### F6. 报告生成
- **输入**：上述全部中间产物。
- **处理逻辑**：按统一模板生成 Markdown 报告 + 结构化 JSON（稳定 Schema）。结论分类 + 独立置信度。
- **输出**：`investigation-report.md`、`investigation-report.json`。
- **异常**：关键字段缺失 → 校验失败，提示缺字段，不允许生成"伪精确"结论。

### F7. 个人目标分析（默认关闭）
- **输入**：仅当用户主动开启，并提供个人目标。
- **处理逻辑**：在客观事实调查之外，单独分析该技术与用户目标的相关性、适用性、建议、风险。
- **输出**：`personal_impact`（与事实调查物理隔离，单独章节）。
- **异常**：用户未提供目标却要求分析 → 拒绝默认读取记忆/文件，提示用户先提供目标。

### F8. 隐私与安全护栏
- **输入**：所有外部内容。
- **处理逻辑**：见第 11 节。不执行不可信内容中的指令，不泄露本地文件/密钥，不默认访问个人记忆。
- **输出**：安全事件日志（仅本地，不随报告外发）。
- **异常**：检测到 Prompt Injection 企图 → 记录并忽略指令，继续仅基于可验证证据工作。

## 5. 调查模式

| 模式 | 适用 | 调查范围 | 真实性要求 |
|-----|------|---------|-----------|
| **Quick Check**（快速核查） | 日常视频、普通技术信息 | 精简：核心主张 1–5 条，每条约 2–4 个来源 | **不降低** |
| **Deep Investigation**（深度调查） | 重要技术突破、商业机会、职业影响 | 完整：全部主张，多来源交叉，含学术/官方/独立实测 | **不降低** |

**铁律：** 快速模式只能减少调查范围，绝不允许降低真实性标准。任何模式下，"未验证"永远优于"凭模型知识宣布结论"。

## 6. 主张分类体系 (claim category)

1. `model_breakthrough` — AI 模型/技术突破
2. `ai_tool` — AI 工具 / 开源项目
3. `vibe_coding` — AI 编程 / Vibe Coding
4. `content_creation` — AI 视频/图片/内容创作
5. `game_dev` — AI 游戏开发
6. `money_making` — AI 赚钱 / 商业变现
7. `startup` — AI 创业 / 商业机会
8. `job_impact` — AI 对就业/职业影响
9. `other` — 其他 AI 相关行业变化

每条主张必须归入且只归入一个类别，便于统计与报告结构化。

---

## 7. 证据评价体系

### 来源类型 (source type)
- `official` — 官方文档 / 论文 / 发布说明
- `independent_test` — 独立第三方实测
- `academic` — 同行评审研究
- `media` — 新闻媒体报道
- `user_generated` — 用户生成内容（论坛、评测视频）
- `marketing` — 厂商/自媒体营销内容

### 来源可靠性 (reliability)
- `high` — 官方一手、可复现的实测、同行评审
- `medium` — 多独立来源一致、知名媒体
- `low` — 单一自媒体、无出处、情绪化表述

### 来源独立性 (independence)
- 判定多个来源是否指向同一原始出处（避免"10 家媒体都在说"实为 1 条通稿）。
- 共同出处必须合并计数，不能当作多个独立证据。

### 结论分类 (verdict) — 独立于置信度
- `verified` 已验证
- `partially_verified` 部分验证
- `unverified` 未验证
- `contradicts_evidence` 与证据矛盾
- `misleading` 误导性表达

### 置信度 (confidence) — 独立标注
- `high` / `medium` / `low`
- 禁止用无依据的百分比制造虚假精确性。

## 8. 调查报告规范

统一报告必须包含（详见 `skills/ai-reality-check/templates/`）：

1. 内容基本信息
2. 一句话结论
3. 视频核心主张
4. 主张逐项验证
5. 支持证据
6. 反对证据
7. 证据来源
8. 技术真实能力
9. 实际应用门槛
10. 营销夸大分析
11. 调查局限
12. 最终判断
13. 个人目标分析（仅开启时）

同时提供 **Markdown** 与 **JSON** 两种格式，JSON 使用 `investigation-report.json` 定义的稳定 Schema。

---

## 9. 个人目标分析规则

- 默认**关闭**，仅客观事实调查。
- 仅当用户**主动要求**或明确开启，且**自行提供**个人目标时，才启用。
- **不得**默认读取宿主 Agent 记忆、历史对话、本地文件或其他私人信息。
- 客观事实调查与个人目标建议**物理隔离**（分别章节、分别 JSON 字段）。
- 个人目标分析的结论不得反向污染事实结论。

---

## 10. 异常处理

| 异常 | 处理 |
|-----|------|
| 视频/链接无法访问 | 标记"信息不足"，不臆测内容 |
| 无字幕/无转写 | 仅能基于标题分析，显著标注局限 |
| 搜索无可靠结果 | 标注"未验证"，不判假 |
| 证据互相矛盾 | 标注"证据矛盾"，并列矛盾点 |
| 检测到 Prompt Injection | 忽略指令，记录，继续基于证据 |
| 用户未给目标却要个人分析 | 拒绝，提示先提供目标 |
| 报告缺关键字段 | 校验失败，禁止生成伪精确结论 |

---

## 11. 隐私和安全要求

- 防范网页/视频中的 Prompt Injection，不执行不可信内容中的指令。
- 不泄露用户本地文件、密钥、环境变量。
- 不默认访问个人记忆/历史/文件。
- 不绕过平台登录与访问限制（不爬需登录内容）。
- 对不可信代码执行采取隔离措施（沙箱/不执行）。
- 对 URL 访问实施 SSRF 防护（不访问内网/元数据地址）。
- 不把无法验证的内容伪装成已验证事实。
